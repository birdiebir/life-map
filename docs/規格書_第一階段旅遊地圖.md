# life-map 規格書：第一階段「旅遊地圖」

> 2026-10-12 建立。設計來源：與使用者逐題確認的設計討論。
> 狀態：**待使用者審閱**。審過才寫實作計畫。

## 1. 目標與成功標準

把旅遊足跡做成可收集、看得到完成度的地圖，讓人生更有遊戲感，也能回答「下次去哪」。

成功標準：
1. 打開一個本機 HTML，就能看到世界地圖（國家＋城市）和台灣地圖（縣市＋368 鄉鎮＋重要景點），依深度上色。
2. 每個去過的地方都有完整紀錄（日期、等級、同行、旅程、回憶、來源），換呈現方式不用重收資料。
3. 過去的足跡大部分由 Google 地圖時間軸和照片 GPS 自動回填，使用者只需確認、補漏。
4. 看得到各套組的完成度，並有「下次去哪」建議。

設計核心：**以深度與回憶計分，不只算打卡數**（避免為了集點而去的護照集章式旅遊）。

## 2. 範圍

**做**：旅遊地圖（世界＋台灣）、時間軸／照片回填、套組完成度、回憶卡、下次去哪、「一起去過」標記、同步摘要到筆記庫。

**不做（這一階段）**：
- 人生成就（運動、學習、冒險、人際、家人、職涯）→ **第二階段**，使用者要求記住，第一階段收尾時主動提出。
- 伴侶自己的足跡（不是一起去的）→ 先擱置。
- 手機版、線上分享、多使用者帳號 → 本機先做，資料層完整即可，之後要做再加。

## 5. 資料模型

### 5.1 地點 ID
| 類型 | ID 規則 | 來源 |
|---|---|---|
| 國家／地區 | `C-` + ISO 3166-1 alpha-3（例 `C-JPN`） | Natural Earth |
| 世界城市 | `CITY-` + GeoNames ID | GeoNames |
| 世界遺產 | `WHS-` + UNESCO 編號 | UNESCO |
| 台灣縣市 | `TW-` + 內政部縣市代碼 | 國土測繪中心 |
| 台灣鄉鎮 | `TW-` + 內政部鄉鎮代碼（TOWNCODE） | 國土測繪中心 |
| 台灣景點 | `TWP-` + 流水號（來源 ID 存在欄位裡） | 觀光署開放資料等 |

每個地點有上層關係：鄉鎮 → 縣市 → 台灣；城市 → 國家；景點 → 所在鄉鎮或國家。

### 5.2 visits.csv（足跡主資料）
| 欄位 | 說明 |
|---|---|
| visit_id | 流水號 |
| place_id | §5.1 的 ID |
| date_start / date_end | 日期（不確定時可只填年或年月） |
| level | 0～5（§6.1），景點只用 0／1（沒去過／去過） |
| together | 是否跟旅伴一起（true／false） |
| trip_id | 對到 trips.csv |
| memory | 一句話回憶（可空） |
| photo | 一張代表照的本機路徑（可空） |
| source | timeline／photo／manual／routine |
| confidence | 自動推定的把握度（高／中／低） |
| confirmed | 使用者確認過才是 true；地圖預設只顯示已確認的 |

**隱私**：visits.csv 只存地點 ID，不存原始座標。原始座標只留在 `private\raw\`。

### 5.3 trips.csv
trip_id、名稱、起訖日期、同行者（自由文字）、性質（旅行／留學／出差／家族旅遊／轉機）、筆記連結。

### 5.4 等級合併規則
- 一個地點的等級＝它所有足跡的最高等級。
- 上層等級＝max(直接紀錄, 所有下層的等級)。例：去過大阪過夜 → 日本至少 4。
- 「一起去過」：只要有一筆 together=true 的足跡就算。

## 6. 規則與參考資料

### 6.1 等級（経県値式）
| 級 | 名稱 | 自動推定（門檻放 config，可調） |
|---|---|---|
| 0 | 沒去過 | — |
| 1 | 路過 | 移動中經過、停留 < 30 分（含轉機） |
| 2 | 踏上 | 停留 30 分～3 小時 |
| 3 | 遊玩 | 同一天停留合計 ≥ 3 小時，或停了 ≥ 2 個點 |
| 4 | 過夜 | 當地時間 02:00～05:00 人在那裡 |
| 5 | 住過 | 60 天內過夜 ≥ 30 晚 |

自動推定的結果一律進 `pending.csv`，使用者確認後才寫進 visits.csv。

### 6.2 世界城市（套組「精選城市」）
1. **候選池**：各國首都＋GeoNames 人口 ≥ 100 萬的城市。
2. **排除**：位於外交部領事事務局旅遊警示**紅色（不宜前往）或橙色（避免非必要旅行）**地區的城市；黃色只標註不排除。
3. **品質篩選**：至少符合一項才收：
   - Euromonitor「Top 100 City Destinations」（國際旅客人數）
   - EIU「Global Liveability Index」排名前段
   - UNESCO 世界遺產所在城市
4. 腳本產生清單附上收錄／排除理由，**使用者審一次**才定案。
5. **例外**：實際去過的城市一律收進地圖，不受篩選影響（篩選只決定「待收集」清單）。

> 實作計畫階段要先確認：各來源目前能不能取得、授權能不能放進 `reference\`、更新頻率。拿不到的來源就從篩選條件拿掉，不硬湊。

### 6.3 世界其他套組
六大洲、世界遺產（UNESCO 全表）、國家總數（以 UN 會員國 193＋台灣為基準，另外顯示地區數）。

### 6.4 台灣（覆蓋最深）
- **行政區**：22 縣市、368 鄉鎮市區，各自是一個套組。
- **景點第一層**：國家公園＋國家自然公園＋國家風景區（約 23 個）。
- **景點第二層**：各縣市代表景點約 200 個，從觀光署觀光資訊開放資料挑（每縣市 5～15 個，依人口與觀光量配額），腳本產生後使用者審一次。
- **景點第三層（主題套組，config 可開關）**：百岳、老街、離島。之後要加別的主題只改 `sets.json`。
- 景點判定：時間軸停留點在景點半徑內（預設 300 公尺，config 可調）就算「去過」候選。

## 7. 資料進來的管線

```
時間軸匯出 ─┐
照片 GPS ───┼→ 停留點 → 判斷落在哪個國家／城市／縣市／鄉鎮／景點（離線，不呼叫外部 API）
手動補 ─────┘        → 推等級 → pending.csv → review（使用者勾選確認）→ visits.csv
```

- **import_timeline.py**：同時支援兩種格式：手機端匯出的 `Timeline.json`（2024 年後新格式，semanticSegments），以及舊版 Takeout 的「Semantic Location History」。Google 已把時間軸改存在手機上，Takeout 裡的時間軸可能是空的；空的就請使用者從 Android「設定 → 位置 → 時間軸 → 匯出」。
- **import_photos.py**：唯讀讀取 Takeout 相簿（E: 外接硬碟）照片的 EXIF GPS 與拍攝時間，補時間軸沒涵蓋的舊旅程。不搬動、不修改照片。
- **review.py**：把 pending.csv 產生成好勾的確認表（CSV 或簡單 HTML），一批一批確認；同一趟旅程可以整批確認。
- **初始資料**：既有的踩點表（約 6 筆），第一次先手動轉進 visits.csv，地圖第一天就有東西看。
- **新旅程（第一階段最後一步）**：收到新的旅遊日誌時，在 pending.csv 加一筆候選，不直接寫 visits.csv。

## 8. 地圖頁（build_map.py → `private\output\life-map.html`）

- **完全離線、自包含**：D3＋TopoJSON 內嵌，不用地圖圖磚伺服器；輸出放在 `private\` 底下，因為含個人資料。
- **世界檢視**：國家依等級上色，城市與世界遺產是點；點擊顯示回憶卡。
- **台灣檢視**：縣市 ↔ 鄉鎮切換，三層景點用不同圖示。
- **我／一起 切換**：一起模式只亮 together=true 的地點。
- **儀表板**：經驗值總分（世界、台灣分開算）、各套組進度條（例：鄉鎮 37/368）、最近解鎖。
- **回憶卡**：地點、等級、日期、同行、照片、一句話回憶、所屬旅程。
- **下次去哪**（規則式，不用 AI）：
  1. 最接近完成的套組，還差哪幾個
  2. 已去過的地方附近還沒去過的鄉鎮／景點
  3. 只去過 1～2 級、值得再深玩的地方
  4. 「一起」模式下：只有自己去過、還沒跟旅伴一起去的地方

## 9. 跟筆記庫的關係

- `private\visits.csv` 是主資料。筆記庫裡的踩點表改成由 `sync_kb.py` 產生的摘要（國家、城市、年份、性質、亮點），不放座標、不放住家位置、不放鄉鎮全表。
- 各趟旅程的詳細內容照舊寫在自己的旅程筆記，trips.csv 只放連結。

## 10. 隱私與安全

- 時間軸原始資料可以推出住家、公司位置，**只放 `private\raw\`**，不進 git、不寫進筆記庫、不寫進開發日誌。
- 照片只讀不寫；不呼叫任何外部地理編碼 API（全部離線判斷）。

## 11. 測試

- 等級推定：各門檻邊界（29／30 分、凌晨 02:00、30 晚）。
- 點落在哪個多邊形：鄉鎮邊界、離島、跨日期變更線。
- 等級合併與套組進度計算。
- 時間軸兩種格式的解析（用假資料 fixture）。
- 用 `private.example\` 假資料跑完整 build，確認 HTML 產得出來、別人拿到也能跑。

## 12. 里程碑

| 階段 | 內容 | 使用者看得到什麼 |
|---|---|---|
| M1 | 參考資料＋資料模型＋地圖頁；匯入既有的 6 筆足跡 | 第一版地圖（少量足跡） |
| M2 | 時間軸匯入＋確認流程 | 大量回填、審 pending |
| M3 | 照片 GPS 回填、城市精選與台灣第二層景點清單（使用者審）、下次去哪 | 完整套組與建議 |
| M4 | 同步到筆記庫、新旅程接入 | 之後自動更新 |
| 收尾 | 開發日誌 → **主動提出第二階段：人生成就** | — |

## 13. 已知風險

- 時間軸只從開啟定位紀錄那天起有資料，更早的靠照片和手動。
- 外部清單（Euromonitor、EIU）可能不是開放資料，取得方式要在計畫階段先確認。
- 地圖檔大小：368 鄉鎮＋全球國界要簡化多邊形，控制在幾 MB 內。
- 遊戲化的反效果：分數只是輔助，回憶卡才是主角；不做排行榜、不做連續天數之類會造成壓力的機制。
